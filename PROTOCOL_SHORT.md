## Протокол — 8 фаз

Проговаривать вслух каждую фазу — на собесе оценивают именно это, тренировка молча его не ставит.
Код писать **в простом редакторе без автодополнения и без запуска** (`.txt`) — как на онлайн-собесе. В LeetCode
вставлять только после фазы 7.

1. **Прочитать и переформулировать** условие своими словами (1–2 мин).
    - Выписать сигнатуру и **тип возврата** вслух: «возвращаю `List<Boolean>` / `String` / `int`». *(против Т)*
2. **Уточнить ограничения + выписать краевые случаи** (1–2 мин). *(против К)*
   Не «подумать про края», а выписать их комментарием над кодом по личному списку:
    - пустой вход / один элемент;
    - **первый и последний индекс** — что у них «слева» и «справа»;
    - два входа **разной длины** — что с хвостом длинного;
    - все элементы одинаковые / всё нули / всё максимумы;
    - `n == 0` или `k == 0` в параметрах;
    - «остаток» после цикла — перенос, последняя группа, незакрытый отрезок.

   Каждый выписанный случай потом обязательно прогнать в фазе 7c.
3. **Brute-force вслух + его сложность**, даже если очевидно, что не пройдёт по времени (1–2 мин). Это то самое
   «получить хоть что-то на доске», что не даёт зависнуть в поиске идеального решения.
4. **Идея оптимального решения** — назвать паттерн (two pointers / DP / …), целевую сложность (2–3 мин).
    - **Стоп-сигнал переусложнения** *(против У)*: если план сводится к перебору комбинаций состояний
      (`if a == '1' && b == '0' && carry == 1 …`) — остановиться и найти формулу. Почти всегда есть арифметика:
      `sum = a + b + carry; digit = sum % 2; carry = sum / 2`.
    - Если в плане 3+ почти одинаковых цикла — можно ли свести в один (`while (i < n || j < m)`)?
5. **План псевдокодом** — по пунктам, до того как начал писать реальный код (2 мин).
    - **Имена задаются здесь**, по роли, а не по порядку *(против И)*: `left` / `right`, `i` / `j` для двух
      входов, `carry`, `maxSoFar`, `write` / `read`. Не `pos1`, `temp2`, `next` для «второго максимума».
6. **Код** (основное время бюджета).
    - Для Easy: если код вышел длиннее ~25 строк — это сигнал У, вернуться к фазе 4.
7. **Самопроверка — три прохода, строго до того, как сказать «готово».**
   ⚠️ Именно этот шаг выпал на прошлом собесе — единственная причина, по которой ошибки нашёл не ты.
    - **7a. Проход «компилятор»** *(против С, Т)* — читать код построчно, глазами javac:
        - заголовки циклов: `for (int i = 0; i < n; i++)` — точки с запятой, `++` / `--`, `<` vs `<=`;
        - скобки и `;` в конце строк;
        - методы API существуют и названы правильно: `sb.reverse()` (не `reversed()`), `s.length()`,
          `arr.length`, `list.size()`, `s.charAt(i)`;
        - синтаксис `switch` (см. Java-ловушки ниже);
        - `return` на всех ветках и тип совпадает с сигнатурой.
    - **7b. Прогон на примере из условия** — трассировка значений переменных вручную, по итерациям.
    - **7c. Прогон краевых случаев из фазы 2** — особенно **первая итерация, последняя итерация и код после
      цикла**. Именно в конце я и не вижу ошибку (1768, 67).
8. **Итоговая сложность** — озвучить time/space complexity и какие edge cases покрыты. Если решение мутирует
   вход (605) — сказать об этом явно.
