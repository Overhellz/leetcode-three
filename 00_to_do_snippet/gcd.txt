class Gcd {
    private int gcd(int a, int b) {
        while (b != 0) {
            int t = a % b;
            a = b;
            b = t;
        }
        return a;
    }
}

/*
Алгоритм Евклида — идея
Ключевое наблюдение:

gcd(a, b) = gcd(b, a mod b)

То есть НОД двух чисел не меняется, если заменить большее число на остаток от деления на меньшее.

Почему это правда (интуиция):

Пусть a = q·b + r, где r = a mod b (остаток).

Любой общий делитель a и b делит и r = a - q·b. И наоборот — любой общий делитель b и r делит a = q·b + r. Значит, множества общих делителей (a, b) и (b, r) совпадают. А раз совпадают — совпадает и наибольший.

Пример:

gcd(12, 8): 12 mod 8 = 4 → gcd(8, 4)

gcd(8, 4): 8 mod 4 = 0 → gcd(4, 0) = 4

Проверим: делители 12 — {1,2,3,4,6,12}, делители 8 — {1,2,4,8}. Общий наибольший — 4. ✅

Почему останавливаемся на b == 0
gcd(a, 0) = a. Потому что любое число делит 0, а a делит само себя. Наибольший общий делитель a и 0 — это a.

Это база рекурсии.

Рекурсивная версия (одна строка)
java
int gcd(int a, int b) {
    return b == 0 ? a : gcd(b, a % b);
}
Читается буквально как определение:

если b == 0 → ответ a;

иначе → gcd(b, a % b).

Итеративная версия (то, что обычно пишут в проде)
java
int gcd(int a, int b) {
    while (b != 0) {
        int t = a % b;  // временно сохраняем остаток
        a = b;          // сдвигаем: b → a
        b = t;          // остаток → b
    }
    return a;
}
Пройдём gcd(12, 8) по шагам:

Шаг	a	b	t = a % b	после: a=b, b=t
старт	12	8	—	—
1	12	8	4	a=8, b=4
2	8	4	0	a=4, b=0
3	4	0	—	цикл вышел
return	4			4 ✅
Ещё пример gcd(48, 18):

Шаг	a	b	t	новые a, b
1	48	18	12	a=18, b=12
2	18	12	6	a=12, b=6
3	12	6	0	a=6, b=0
return	6			6 ✅
Проверка: 48 = 6·8, 18 = 6·3, 8 и 3 взаимно просты → gcd = 6. ✅

*/
